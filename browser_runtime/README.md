# 浏览器运行时原型

独立宿主服务，使用 Google Chrome 无头运行、持久化资料、实时画面和人工接管。固定使用无头模式（`headless: true`），默认静音，无原生窗口或 Dock 入口。已接入 HayBot 后台的登录、Bot 工作台和 HTTP/WebSocket 中继；已接入抖音自主浏览循环与 Owner 私聊 QQ 指令。

当前实现和实机验收范围为 **macOS arm64**。macOS Intel 有架构检查分支，未实测；Windows/Linux 只有安装路径发现，身份和启动流程尚未实现，会阻断启动。

## 启动

推荐从项目根目录双击 **启动浏览器.command**（macOS），无需手工运行 npm。启动入口在服务启动前检查 Node.js 22 或更新版本；缺失或不兼容时打开官方安装页，提示下载安装 .pkg，安装后按回车重检。依赖缺失时自动执行 npm ci；服务已启动时直接提示返回后台。关闭启动窗口会停止服务。首次使用还需按下文配置后台的运行时地址与访问码。

手动启动前置条件：Node >=20、官方 Google Chrome 稳定版。缺少 Chrome 时，页面提供 [Google 中国安装入口](https://www.google.cn/chrome/)，由用户安装后重新检测。不会安装 Playwright Chromium 或改用其他浏览器。

在项目根目录运行：

```sh
npm --prefix browser_runtime ci --ignore-scripts
npm --prefix browser_runtime start
```

访问 `http://127.0.0.1:17322/`，将本机 `.browser-runtime/token` 中的访问码填入连接表单。终端只显示访问码文件路径，不显示内容。重启服务后需要重新连接。

进入页面自动检查宿主、Node、工作目录、Chrome 产品/Google 签名/架构和真实隐藏启动连接。通过后检测项收起。选择原型 A/B，点击启动、接管，再打开“测试页”。可在画面内点击、滚动、拖动、滑动、键盘输入；中文也可通过画面下方输入框发送。支持标签管理、放大查看和 Esc 收起。

画面操作默认为“自动”：鼠标按住移动对应网页原生拖动（滑块、文字选取、拖动控件），触摸按住移动对应滚动页面；滚轮/触控板在鼠标所在的网页位置滚动，也支持内部独立滚动区域和横向滚动。选“滑动”可用鼠标按住上下/左右推来滚页；选“拖动”可强制让触摸操作拖动控件。滑动模式转为桌面网页滚轮事件，不模拟远端移动浏览器的多点触摸或缩放。

画面边缘黑边不会触发输入；按住后移出画面仍可松开。失焦、隐藏页面、切换标签、退出接管或断线均取消手势；后端也为中断手势设置超时释放。移动和滚轮事件合并待处理数据，防止慢网络下动作无限排队。

接管绑定当前画面连接；断线会撤销权限，重连后需重新接管。结束接管保留浏览器；停止关闭本服务拥有的浏览器进程，保留独立资料。Ctrl+C 正常退出服务并关闭所拥有的会话。不会连接或关闭用户日常 Chrome。

可选环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HAYBOT_BROWSER_PORT` | `17322` | 本机开发端口 |
| `HAYBOT_BROWSER_DATA` | 项目 `.browser-runtime/` | 私有访问码及 `profiles/{sessionId}` 资料目录 |

数据目录已加入 Git 忽略。请勿上传访问码、Cookie、资料目录。原型 A/B 是合成验收资料，不代表两个正式 Bot。

## 接入正式后台

宿主运行时仍在用户系统中启动，Chrome 不安装到 Docker。后台只负责鉴权和转发。在项目私有 `.env` 添加以下变量（不要把真实访问码写入仓库）：

```dotenv
BROWSER_RUNTIME_URL=http://host.docker.internal:17322
BROWSER_RUNTIME_TOKEN=填写本机.browser-runtime/token的内容
```

如果后台直接运行在宿主，地址使用 `http://127.0.0.1:17322`。后台转发时默认发送 `Host: 127.0.0.1:端口`；自定义宿主代理地址时可用 `BROWSER_RUNTIME_HOST` 明确指定服务允许的 Host。WebSocket 的 TCP 连接目标使用配置的地址，握手 Host 使用允许值，不重复发送 Host。仍仅监听 loopback，不开放 Chrome 调试端口。

应用新配置需要重建/重启后台。登录 HayBot 后，从左侧“浏览器工作台”进入；页面用弹窗检测执行宿主，通过后自动关闭，不再常驻占位。Chrome 缺失时显示中国官网安装入口。服务未连接时提示从本机启动入口检查 Node.js 和服务状态；Docker 后台不能直接判断宿主是否安装 Node.js。环境通过后，启动、接管，输入完整网页地址即可操作。地址和访问码只配置在服务端，管理页面无需再次填写访问码。

每个已登记且未归档的 Bot 固定使用 `bot-{bot_id}` 会话和独立持久化资料，客户端不能另选 sessionId。画面连接、租约和操作均绑定同一个 Bot 及当前管理登录；页面断开或退出登录会撤销控制。归档 Bot 时先停止对应浏览器，资料保留。

### 无头运行与平台范围

2026-10-29，按用户新方案恢复固定无头模式：`headless: true`。此节取代此前普通模式默认值与实验性无头开关。运行时启动时也强制无头，旧客户端请求 `headless: false` 会被拒绝；不自动切换有界面模式。

历史 `settings/{sessionId}.json` 在读取时原子迁移为 `{version:2,headless:true}`，包含普通模式和旧实验性设置。新 Bot 同样默认无头，不需要风险确认。资料目录、Cookie 和主人登录隔离标记不改动；迁移后需重启已有 Chrome 才改变实际模式。

浏览器工作台提供抖音和 B 站快捷入口，直接导航当前 Bot 的独立页面。移除小红书专门的 300012 检测和提示，以及旧手机配置中的小红书入口，历史手机配置和历史记录保留。通用地址栏仍支持 HTTP/HTTPS，不对登录跳转、短链接和媒体资源增加两个主域名的限制。

独立 Chrome 始终使用 `--mute-audio`，不改系统音量或日常浏览器。实时采集、放大、接管、点击、滑动、拖动和中文输入继续可用；切换工作台标签不调用 `bringToFront()`。移除有界面模式的原生窗口状态恢复代码。

遇到需要人工处理的登录或验证，通过工作台接管，并使用登录隔离；不自动弹出本机 Chrome。当前抖音支持搜索、推荐、打开已观察视频、播放抽样与读取评论。发布评论、真实 @、点赞、站内分享和受限私信回复已接入，关注尚未接入；真实站点受登录/验证码影响，不能把合成页验证当作账号流程验收。

“主人登录”必须先接管。开启后阻断 ARIA/模型观察，手动画面仍可使用；退出接管、关闭页面、停止或重启浏览器都不会自动解除隔离。请离开密码/验证码页面后点击“完成登录”，确认解除。接管期间也阻断模型观察，观察过程中发生接管或页面变化会丢弃已捕获结果。自主浏览只有在未接管、未开启登录隔离时才能抽样画面供图片模型理解，不提供 QQ 任意远程控制入口。

## 接口与边界

只监听 `127.0.0.1`；HTTP 使用 Bearer 访问码或交换得到的 HttpOnly/SameSite Strict Cookie。Host 与 Origin 必须匹配服务本机地址。不会开放 Chrome 调试 TCP 端口，驱动通过进程管道连接。

| 接口 | 用途 |
| --- | --- |
| `POST /api/connect` | Bearer 换取进程有效期内的网页 Cookie |
| `GET /api/health` | 鉴权连接检查 |
| `GET/POST /api/environment` | 缓存检测/主动重新检测 |
| `GET /api/sessions/{id}` | 会话状态、标签与画面版本 |
| `POST /api/sessions/{id}/start`、`stop` | 幂等启动/停止 |
| `GET/POST /api/sessions/{id}/settings` | 读取/确认固定无头设置；拒绝关闭无头，仅停止时保存 |
| `POST /api/sessions/{id}/claim`、`release` | 绑定实时连接的操作租约 |
| `POST /api/sessions/{id}/action` | 有限的导航、标签、坐标、滚动、pointer 手势和文字/按键操作 |
| `GET /api/sessions/{id}/observe` | 当前页有限长度 ARIA 快照 |
| `POST /api/sessions/{id}/login/begin`、`login/finish` | 持当前租约开启/解除持久化登录隔离 |
| `WS /api/sessions/{id}/live` | 只读状态和 JPEG 画面；初始状态返回 connectionId |

动作必须携带当前 `lease/generation/tabId`；执行队列实际执行前再次校验。导航、切换标签和接管使旧输入失效，失败的动作不自动重试。`claim` 需要同一会话仍在线的 `connectionId`。

`pointer` 动作使用同一 `gestureId`，分为 `start/move/end/cancel`；`start` 额外指定 `mode: drag|swipe`，除 cancel 外均带 viewport CSS 坐标 `x/y`。`scroll` 可携带 `x/y`，先移动到实际目标再转发滚轮。原型没有任意脚本执行接口。

多个查看端共享一次活动页采集，慢端丢弃帧；前端只解码最新待处理帧。当前采用 JSON/base64 便于原型验证，尚未做慢网络长时压力、CPU/带宽基准和跨域复杂页面验收。

17322 上仍保留直接访问宿主服务的开发页面；正式工作台走 HayBot 管理登录和 Bot 中继。现有后台为单个管理员账号，不包含多个管理员之间的租户分权。没有向 QQ 群友暴露浏览器控制、观察或截图入口。抖音模型执行循环与 Owner 私聊回传已接入；声音理解暂未接入，抖音互动按下述权限设置执行。

## 抖音自主浏览

在「浏览器 → 抖音自主浏览 → 设置」开启功能，角色兴趣、主人喜好与内容筛选分别填写。迁移旧版用户手填的兴趣但默认不开启浏览器执行权限，不从人格生成兴趣。使用当前 Bot 的对话模型，供应商需声明支持图片。没有音轨/ASR，观看以实际播放器推进、截图及可见字幕为依据。

管理端接口（都需要管理员登录且 Bot 有效）：

- `GET/PUT /api/bots/{id}/browser/douyin/config`：配置；QQ 授权绑定当前接入账号。
- `GET/POST /api/bots/{id}/browser/douyin/tasks`：查看/开始任务。
- `POST /api/bots/{id}/browser/douyin/tasks/{task}/stop`：撤销操作权并停止。

开启 QQ 并填写 Owner ID 后，仅该 Owner 私聊可用 `/抖音 目标`、`/抖音进度`、`/停止抖音`，也支持识别当前自然语言委托；官方 QQBot 与 NapCat 共用入口。历史任务和引用消息只用于补全指代。收到 QQ 回执才记录已发送，超出官方被动回复时效则跳过，不假称送达。后台发起任务在后台查看结果，通常不另发 QQ。遇到登录、安全验证或短信本人验证时暂停操作；若已开启 QQ Owner 授权并绑定当前接入账号，则按私聊人格发送一次求助，后台保存发送回执。后台或自动任务使用独立消息，官方 QQBot 需具备主动推送权限；拒绝或未确认时显示未送达，不重发。

宿主新增 `douyin/begin`、`douyin/act`、`douyin/end`。每次执行绑定 Bot、标签页、随机任务 capability 与页面 generation，模型不能读取 capability，也没有任意 JS/URL 执行工具；评论等写操作另受服务端授权与真实回执约束。接管立即撤销排队动作，进行中的观察/观看会丢弃结果；120 秒无续约自动撤销。取消 begin 的竞态使用预分配 runId 与撤销记录阻止迟到复活。服务重启将旧任务标记中断，不自动重放。

每次观看抽取 3 张临时图片传给视觉模型，不将图片或音视频下载到任务库；任务步骤只持久化内容元数据、选择理由和播放器证据。无播放推进会先按配置等待缓冲。验证码、登录弹层和跨平台跳转会阻断执行。模型自行安排浏览路线与结束时机，步数/时长只是上限；结束需要有真实播放推进证据。

「设置 → 观看策略」按 Bot 保存 `viewing`：可开关长视频分段跳看；跳看起始时长与最长视频时长均为 1–120 分钟，默认 3 和 60 分钟；每段观看 3–30 秒，默认 15 秒；两段之间跳过 0–3600 秒，默认 0（自动分散选段）。超过最长时长不打开或播放；等于跳看起始时长仍正常观看，等于最长时长仍允许观看。关闭分段跳看时最长时长限制继续生效。开始任务时将设置固定传入宿主并核实确认，防止旧运行时忽略用户配置；任务进行中不能修改配置。

自动分散选段时模型可用 `start_at` 指定秒数；固定跳过间隔时以用户间隔为准，从上一段结尾向后跳。每段时长由用户配置决定，不被模型覆盖；缓冲等待继续当前片段。不要求看完固定数量片段，可随兴趣离开。跳转确认后才播放，跳过区间不计入 `sampledRanges` 或累计 `coverageRanges`，分段预览仍标记 `partial`。跳转失败或默认预览结束交回模型规划，不作为缓冲自动重试。时长暂不可得时不猜测，后续观看前重新检测。模型思考时暂停播放器。旧配置缺少 `viewing` 时使用上述默认值，不修改原有兴趣或账号授权。

音频转写暂缓；验证码仍由主人实时接管处理，不自动解题或重复尝试。

“分享给我”通过抖音站内分享给配置的 Owner，明确要求 @ 时走真实评论提及；明确索要链接时从已观看视频证据提取 URL，不另开 Chrome 验证链接。真实视频卡片的 `parsedContent.itemId` 与服务端消息 ID、发送方向、Owner 会话一起构成分享回执，点击按钮或提示条不算送达。分享后等待目标会话加载，仍无法确认时保留 unknown，禁止重发。

「设置 → 抖音互动 → 私信监控」提供关闭、随浏览任务运行、24 小时监控三档。旧版已经开启私信的配置升级后保持“随浏览任务运行”，不会自动扩大为全天常驻。独立后台私信页仅由 DOM 变化通知新消息，不再设置固定秒数轮询；页面重新加载时会重新安装观察器并立即核对一次。后端独立私信协程及模型调用不等待视频主模型的下一次决策。消息页有独立操作队列与会话修订号，视频 watch 队列被占用时仍可打开、核验、回复私信；不会切走工作台活动视频。进入会话前核对账号身份和关注关系，回复仍经过原有权限、白名单、额度、来信去重与真实发送回执。模型生成期间出现新来信会丢弃旧草稿重新观察。24 小时模式在浏览器已启动且未被主人接管时独立运行；浏览任务开始时自动让位并改由任务内通道处理，任务结束后恢复。撤销、接管或主人登录会关闭私信页、撤销消息操作。共享同一 Ollama 实例时，模型推理本身可能由服务端排队；独立页面不等于外部模型无限并发。本轮未接入抖音 Owner 与 QQ 的跨平台聊天记忆。


正常观看误传 `start_at` 时返回未执行的 `actionError`，交回模型按真实播放策略纠正，不直接结束整个任务；同一错误连续三次仍未纠正则停止并保留原因。任务步骤保存失败参数和反馈。累计观看区间按真实视频 ID 与时长归并，重新进入或 CDN 地址变化不丢失，也不重复累计重叠区间；单次播放采样仍要求媒体来源一致，观察中提供当前位置与累计区间。


「设置 → 空闲时段自动刷」保存 `auto_browse.enabled`（默认关闭）和 `daily_video_limit`（默认 30，1–1000）。调度使用北京时间：非节假日周一至周五 09:00–12:00、14:00–18:00 为高峰，其余空闲；周末即使调休上班也视为空闲。当前内置国务院公布的 2026 年节假日安排；未录入的年份显示提醒，并保守按平日高峰约束执行，不猜测节假日。

每天累计所有任务里真实推进至少 1 秒的不同视频 ID；缓冲、跳过和重复观看不增加数量，重启后计数保留，北京时间零点换日。自动任务沿用角色兴趣、内容要求、观看策略和全部互动额度。高峰到来、达到每日数量或点击暂停时，在当前操作后保存进度，后续空闲时段建立新任务补足剩余数量；不会中途打断已提交的发送。主人接管、登录、手动停止及异常阻塞会暂停当日自动启动，可在后台恢复。无任务冲突才启动，单次时长/步骤上限继续生效；正常单次结束后稍歇再运行，错误不会密集重试。自动任务不向 QQ 另发完成通知。

### 互动结果核对

点赞使用当前视频可见的互动栏与真实指针点击，不点击隐藏播放器控件；已点赞不再点击。以匹配视频 ID 的平台提交回执确认，缺回执时用临时后台页重新读取平台视频详情中的当前账号点赞状态。评论回执按本次请求的视频、正文和当前账号的 sec_uid 或 uid 核验；响应省略视频 ID 时使用已匹配的提交请求，不因单一缺字段误判。短信本人验证独立识别，不把验证页内容、手机号或验证码传给模型。

最近互动包含全部待核对记录及最近 50 条其他记录。结果未知继续占用额度并阻止重复提交；后台“核对结果”通过 `POST /api/bots/{bot_id}/browser/douyin/operations/{operation_id}/verify` 只读取原账号、视频评论或原 Owner 会话，不重发操作。只有真实点赞状态、同账号同视频同正文的评论 ID，或发给同一 Owner 的视频卡片及消息 ID 才能确认。未找到不等于失败，保持待核对。核对记录单独留审计，历史步骤展示后续核对结果，原始步骤保留。核对期间不能运行新任务，主人接管仍可随时撤销核验。

### 工作台布局（2026-10-29）

实时画面位于「工作台」，接管后才展开导航、标签和文字工具；更多菜单包含重连、环境复检和停止。画面按真实视口、JPEG 质量 90 采集，避免默认 800 像素缩图被放大。任务与互动各自切页，当前任务进度和自动浏览计数保留在工作台底部。浏览设置放入分类抽屉，保留原有权限、观看策略和峰谷调度配置；任务详情展示完整步骤、播放覆盖与 QQ 回执。取消设置恢复原保存值。切换记录页不卸载画面连接。

### 互动详情

互动记录直接展示视频标题、互动类型、评论/回复/分享附言正文、接收人和「打开视频」链接。新操作在提交前保存视频标题快照；分享附言关联已确认分享的视频卡片，而不是当时打开的页面。历史记录按原任务和准确的视频 ID 从步骤中补回标题，正文来自原始提交载荷。缺失资料明确标注，不猜测标题。视频链接仅由有效抖音视频 ID 构造，不展示任意外部链接；待核对仍显示原提交内容和未知状态，不因此改成成功。

独立私信通道在打开未读会话后，会先持久保存真实来信标识，再调用模型并发送。模型可返回规定的 `reply` JSON，也兼容不含控制结构的自然纯文本；畸形 JSON 会在同一次处理内纠正。若模型、服务或页面中途失败，来信不会因抖音已清除未读角标而丢失，后续任务会从待办恢复。只有取得发送回执、明确跳过，或确认会话最后一条已经由当前账号发出时才结清；发送方向不明时保留待处理状态，不猜测成功，也不自动重复发送。

接管时支持鼠标/悬空笔的 hover：普通移动会转发到远端 Chrome，可打开网页的悬停菜单与提示层；移出画面、窗口失焦时发送离开事件以收起弹层。悬停不按鼠标键，触摸操作沿用手势；拖动时不会被迟到的悬停消息打断。移动按约 33ms 合并，仅保留最新待发送位置，断线、换标签或租约失效时丢弃旧位置。正式工作台与宿主开发页使用同一输入实现。

实时画面和整个浏览器外框一起等比例适应窗口，不在全宽黑色容器里显示缩小画面。顶部区域在较矮的电脑窗口中收紧；任务和自动浏览状态不再挤占画面高度，必要时允许页面向下滚动，优先保留可读尺寸。推流原始像素保持不变，接管与放大模式沿用相同坐标映射。

「工作台 → 查看进度」在视频右侧以动画展开进度面板，不使用遮罩，也不卸载画面或撤销接管。面板展示当前任务、最近步骤、完整执行记录和 QQ 回执，每 3 秒随原任务轮询更新，可在面板中停止当前任务。任务完成后保留最终进度；关闭按钮、原进度按钮或 Esc 可收起。850px 以下改为视频下方展开，避免挤占视频。历史任务仍可从「任务记录」查看完整详情。支持减少动态效果偏好。


## 浏览经历与聊天回忆（2026-10-30）

浏览器工作台新增「浏览手记」。仅有实际播放推进证据的视频形成经历，包含标题、作者、视频链接、播放覆盖和当时想法；总结沿用完成任务时已经生成的自然语言结果。后台、QQ 与自动任务一并保存，运行中持续更新，结束后保留。支持搜索、分页、单份手记停用/恢复聊天回忆和删除。删除保留墓碑，历史补生成不会复活；停用不删除既有 QQ 聊天。历史任务可从页面补生成，最多处理最近 200 个任务，未看过的视频不凭标题编造经历。

QQ Owner 私聊会检索当前 Bot/接入账号/Owner 绑定下的手记，不再只带入从 QQ 发起的三条结果。最近经历和标题/内容相关经历共同参与检索，支持北京时间今天、昨天、前天和日期查询；无需配置嵌入服务。正文与观看证据分开提供，不把采样当完整观看，不自动改写用户设置的角色兴趣或主人的喜好。普通群聊与其他人私聊不带入这些私人经历。报告删除、停用及 Owner/账号变更会使正在生成的旧聊天回复失效。

已有主动聊天的生成阶段可选取运行中任务刚看过的具体视频作为话题，与日程、对话共同选题；仍遵守原主动消息总开关、免打扰、频率、额度和未回复限制。仅在收到 QQ 成功回执后消费话题，按 Bot/接入账号/接收者/视频去重，预览不消费，不逐条播报进度，也不会因为写手记另发完成报告。

## 自定义自动浏览时间

「浏览设置 → 自动浏览」保留自动刷总开关，新增「仅限空闲计价时段」（默认开启）与「自定义允许浏览的时段」（默认关闭，保持已有行为）。可填最多 20 个北京时间区间，支持多个区间和跨午夜，如 08:30–08:59、19:00–22:30 或 23:00–01:00。关闭计价限制后高峰也可运行，但自定义作息窗口仍生效。两个限制同时开启时取交集；结束时刻不包含在时段内。离开允许时段后完成当前操作暂停，下次允许时段继续；每日计数、主人暂停、接管和额度限制仍生效。页面的下次可运行时间按实际交集计算，不会简单跳到计价空闲的午夜。
