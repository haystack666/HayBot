# HayBot · QQ AI 机器人配置平台

## 管理界面

HayBot 使用 React、shadcn/ui 与黑白灰配色，支持浅色、深色和跟随系统；主题偏好保存在当前浏览器。手机端通过顶部菜单打开导航，桌面端支持折叠侧栏。

机器人管理位于 `/bots`，各机器人页面使用 `/bots/{bot_id}/overview`、`qq`、`providers`、`rules`、`memory`、`schedule`、`diary`、`proactive`、`chats`、`logs`。共享供应商目录也可直接访问 `/providers`。旧 `/ollama` 与 `/bots/{id}/ollama` 自动转入对应 Bot 的模型供应商页。URL 同时保存机器人与页面，刷新、登录、前进后退保持选择。聊天记录的会话和列表/气泡视图也保存在 URL 中。原有 `/overview` 等地址会转入默认机器人的对应页面，根地址 `/` 跳转到机器人管理。

配置修改后点击“保存更改”，或用“取消更改”恢复已保存值。数字输入框允许临时留空，保存时检查必填字段和取值范围。


Python FastAPI + SQLite + React（JavaScript）+ shadcn/ui，使用 Docker Compose 运行。网页仅用于配置和管理，实际对话在 QQ 中进行。

## 启动

```sh
python3 scripts/setup.py
docker compose up -d --build
```

首次启动会自动启动 Ollama 并拉取 `qwen3:0.6b` 小模型，下载时间取决于网络。打开 http://localhost:8080，使用根目录 `.env` 中的 `ADMIN_PASSWORD` 登录。首次登录后配置 QQ AppID、AppSecret，模型服务地址使用 `http://ollama:11434`，选择 `qwen3:0.6b`，保存并启动机器人。

配置网页在 8080 端口提供本机与局域网访问，其他设备可打开 `http://电脑的局域网IP:8080`，仍需管理密码登录。Ollama 不映射宿主机端口，仅在 Docker 网络内部提供服务。

机器人运行在 Python 后台，关闭网页不会停止；Docker 服务设置为自动重启。首次需手动启动机器人，此后会记住启停状态，容器重启时自动恢复。点击“停止机器人”会关闭自动恢复。保持 Docker Desktop 运行、电脑不休眠，机器人才能持续在线。

## 功能

- 多机器人同时在线：新建、重命名、独立启停、切换配置、归档、恢复与永久删除；每个 Bot 独立 QQ 凭证、模型、人格、主动消息策略、接收者、提醒、会话与统计。
- 按 Bot 查看聊天记录：快捷列表与聊天气泡两种形式，支持会话选择、搜索已加载会话、分页加载和自动刷新；只读展示，实际发送仍在 QQ 中进行。
- QQ 官方 WebSocket：自动获取网关、鉴权、心跳、Session 恢复、退避重连。
- 单聊自动回复、群聊 @ 回复；事件权限以 QQ 开放平台实际开通情况为准。
- 图片/表情包识别：支持单聊与群聊 @ 的纯图片、图文混合消息，GIF/WebP 动图抽取首帧、中间帧和末帧供视觉模型识别；仅处理 QQ 事件实际提供的图片附件。
- 主动消息：选定单聊接收者，配置定时问候、随机间隔搭话与一次性提醒；支持预览、能力测试、发送记录与跳过原因。
- 使用 QQ 官方 HTTP API 发送文本回复，携带 `msg_id` 和 `msg_seq`。
- 多个可命名的模型供应商：Ollama（本地/外部）、OpenAI Compatible、OpenAI Responses、Anthropic Compatible、DeepSeek；支持 API Key、默认模型、模型列表、连接/生成测试、温度、超时和输出 Token 上限。
- 系统提示词、上下文轮数、回复长度、冷却配置。
- SQLite 持久化配置、日志、去重记录和上下文；个人历史、记忆及日程按群成员隔离。QQ 官方和 NapCat 均向模型提供当前群聊/单聊场景、真实发送者标识、提及对象及引用对象；昵称不作为身份凭据。群聊回复参考本群最近 30 分钟内已收到的公开发言（最多 20 条、约 6000 字符），逐条标记发言者；不会读取其他群或单聊。清空上下文、重置及遗忘的来源屏障同时约束这部分背景，保留轮数为 0 时关闭背景。官方 OpenID 与 NapCat QQ 号不自动映射；未被平台推送或被现有 @ 策略过滤的消息不作为已读背景。
- 在「QQ 接入」中可选择群聊默认模式，并为当前账号已收到消息的各群单独设置「仅 @ 回复／自然参与／安静旁听／不参与」及参与积极程度。新配置默认仅 @，已有群不会自动改成主动参与。自然参与和旁听根据用户手填兴趣和本群公开发言判断是否开口；兴趣留空不从人格推导。整群连续消息合并判断，一轮至多选择一条消息回应，沉默不产生气泡；语境变化时复核待发正文，仍有新消息则停止旧回复。群级间隔及每小时上限限制主动插话，直接 @ 可绕过主动频率上限。决定参与、沉默、取消和实际送达分别记录在页面及运行日志中。判断失败保持沉默，不向群里发送错误占位；待处理消息加密保存，发送结果未知不自动重发。自然参与目前仅发送文字，不读取个人表情包选择记录。
- 群聊人格按平台真实发送者分流：「角色名字」保持身份一致，「群聊 Owner」按当前接入账号绑定真实发送者 ID。Owner 使用「回复策略」中的原角色人格，其他群友使用公开人格；仅 @、自然参与和旁听均遵循这一规则。自然参与和旁听仍只参考公开群聊，不读取私聊记录、个人记忆、日程或手机结果。昵称、群主身份、引用和提及不能冒充 Owner，官方成员 OpenID 不猜测与 QQ 号或私聊 OpenID 的关系；换接入账号不会沿用旧账号的 Owner 绑定。群聊公开人格不会覆盖角色名，也不适用于 Owner；参与判断不加载公开人格来评价 Owner。角色名、平台昵称和明确发给当前 Bot 的 @ 会提供给模型，历史回复认错名字不能覆盖当前身份。Owner 未配置时不猜测私人关系；这项绑定不授予手机权限。
- 多个 Bot 同群时，参与判断和回复上下文逐条标明当前 Bot 自己的发言、其他账号的发言和实际被 @ 的对象。其他 Bot 的公开发言保留为群聊背景，不能认领成自己的历史或经历；仅 @ 其他账号的消息不作为当前 Bot 的回复目标，同时 @ 当前 Bot 或 @ 全体不受此限制。未明确点名的追问按公开上下文判断，不默认全部接给自己。NapCat 仅包含 @、没有文字的消息也会保存并按实际提及对象判断。
- 「与 Owner 的公开关系」保存用户允许向群友说明的关系事实；被问起时自然承认已填写的关系，公开人格只改变对群友的交流风格，不能否认关系或编造相识、见面等经历。只关联当前账号绑定的 Owner；公开称呼来自该 Owner 在同群的真实发言，昵称不授予权限。不会读取私聊记录来回答群友。
- QQ 官方全量群消息采用 `GROUP_MESSAGE_CREATE`（与 @ 事件使用同一 Intent），需要先在开放平台开启「接收所有消息」，平台未推送时只能处理收到的 @。全量事件的自我提及通过官方 `GET /v2/groups/{group_openid}/bot_state` 的 `member_openid` 核对，按接入账号和群分别缓存；登录 READY 用户 ID、昵称或 `bot=true` 不能替代群成员身份。接口失败会记录日志并短暂退避，不猜测其他机器人的身份。NapCat 自然参与模式接收非 @ 群消息，不需要关闭旧的 `group_require_at` 兼容字段；参与策略以 `group_chat` 配置为准。手机任务仍只允许后台授权 Owner 私聊发起，群聊参与不增加设备权限。
- 管理密码登录、同源校验、HttpOnly Cookie；AppSecret 加密存储且不回传前端。
- 接收、成功回复、异常和输入/输出 Token 累计统计持久化到 SQLite，容器重启与清空上下文不会清零。Token 采用 Ollama 的 `prompt_eval_count`、`eval_count`，模型已消耗而 QQ 发送失败的用量也会计入。
- 首次升级统计功能会根据现存的去重记录与回复日志恢复消息计数；旧版未保存 Token 用量，因此历史 Token 不补算。已被旧版清理的历史记录无法恢复。
- 单后台工作进程，每个 Bot 独立 WebSocket 和调度任务、最多同时处理 4 条消息；多个 Bot 可同时在线。共享 Ollama 的模型推理请求排队执行，以适应当前单模型内存设置；忙碌、冷却期间或超时消息会跳过。发送失败不会自动重发，避免重复回复。


## 私人日记

每个 Bot 的「角色与对话 → 私人日记」提供日记设置、按日阅读、手动补写、修改记录与删除。默认北京时间 23:30 自动回顾当天；可修改时间、时区、是否参考群聊及写作偏好。机器人需保持运行才能自动写作；重启只补齐最近一个到期日，不批量编造旧日记。同一天自动回顾一次，手动补写保留历史版本；失败保留旧正文，自动失败最多重试三次。删除会清除正文和版本，不自动重建。

日记写给角色自己，允许 Owner 在已登录的管理后台查看。沿用原角色人格，允许想念、吃醋、委屈等主观感受，不把猜测当事实，不通过情绪施压。写作后会依据素材再核对正文，删减缺乏支持的具体经历。素材只来自当前 Bot、当前接入账号、指定日期：后台绑定 Owner 的私聊，以及可选的已收到群聊、绑定 Owner 发起且确认完成的手机任务。日程仅作计划参考，不能当成真实执行结果。换账号不沿用旧日记、Owner 或设置，清空/重置来源后旧日记不再进入聊天上下文。

「Owner 私聊账号」必须填写对应平台的真实私聊身份：NapCat 使用 QQ 号，官方使用单聊用户 OpenID，不能按昵称猜测，不能用群成员 ID 代替。留空时不读取任何人的私聊，也不向聊天提供日记。允许自主分享时，仅向这个 Owner 的私聊/已有主动聊天提供少量片段，由角色按语境决定是否提起；群聊和其他成员的私聊不读取日记。写作本身只保存，不发送 QQ 完成通知或全文，不自动创建长期记忆、日程调整或手机任务。日记正文、素材索引及各版正文使用当前 Bot 密钥加密保存。

管理 API 均要求登录，前缀 `/api/bots/{bot_id}/diary`：`GET /` 查看设置和状态，`PUT /config` 保存设置，`POST /write` 以可选 `day`（YYYY-MM-DD）写作，`GET /entries` 分页列出日记，`GET /entries/{id}` 读正文，`GET /entries/{id}/versions` 查看版本，`DELETE /entries/{id}` 删除。

## 多机器人管理

访问“机器人管理”新建 Bot，填写该机器人的独立 QQ AppID / AppSecret，选择模型、设置人格与主动消息，然后单独启动。多个 Bot 可以同时保持 QQ 连接，停止、保存配置或归档一个 Bot 不会停止其他 Bot。同一个官方 AppID 不允许同时绑定多个未归档 Bot，以免连接与消息处理冲突。

“新建机器人”默认打开 QQ 官方扫码添加：使用手机 QQ 扫码，在 QQ 官方页面选择/创建机器人并确认授权，回到 HayBot 点击“完成添加并启动”，即自动保存 AppID 和加密的 AppSecret，并立即启动连接 QQ，无需再扫码或手动启动。名称可选，留空按 AppID 命名。新 Bot 先使用默认模型与人格，之后可停止它并调整配置。启动失败时保留已添加的 Bot 和凭证，在运行概览显示原因，可直接重试启动。需要手动输入时点击“改用手动添加”，原有方式仍保留。

扫码使用腾讯官方连接器公开采用的 `q.qq.com/lite/create_bind_task` 与 `poll_bind_result` 协议，Python 后端独立实现；二维码指向 `https://q.qq.com/qqbot/openclaw/connect.html`。QQ 授权页默认可能显示“第三方机器人”，平台名称展示需与腾讯合作配置。参考：[腾讯维护的官方插件](https://github.com/tencent-connect/openclaw-qqbot)、[官方连接器](https://www.npmjs.com/package/@tencent-connect/qqbot-connector)。仅在用户确认官方授权后读取结果，不使用个人 QQ 协议登录。

每次扫码独立生成 32 字节绑定密钥，在后端用 AES-256-GCM 验证并解密官方返回的 AppSecret，随后使用 Bot 的原有密钥加密入库。绑定密钥与 AppSecret 不返回浏览器、不写入日志；二维码在浏览器本地编码，不经过第三方二维码服务。未确认添加前不创建本地 Bot；关闭或取消窗口、退出管理员登录及重启服务会使待绑定会话失效。会话最长保留 10 分钟，二维码也可能被 QQ 提前判定过期，页面支持重新生成。

若授权的 AppID 已在平台中配置，页面显示现有 Bot，必须明确确认“更新现有机器人凭证”，不会创建重复 Bot；更新前需停止该机器人并等待处理结束，原模型、人格、上下文、聊天档案和统计保留。已归档 Bot 需要先恢复，再重新扫码。扫码完成添加或确认更新凭证后立即启动 QQ 连接，并记住自动恢复状态。关闭扫码弹窗不会停止已添加的 Bot。

扫码 API（管理员登录保护）：`POST /api/qq/qr` 申请会话，`GET /api/qq/qr/{session_id}` 获取二维码/状态，`POST /api/qq/qr/{session_id}/complete` 确认添加（JSON：`name`、`replace_existing`），`DELETE /api/qq/qr/{session_id}` 取消。状态接口不包含解密密钥或 AppSecret。接口来源为官方连接器当前协议，后续如腾讯调整流程需同步适配。

侧栏的“当前机器人”用于切换；页面地址包含 Bot ID，刷新不会切回其他机器人。配置有未保存修改时，切换机器人会提示确认。修改模型或人格仅清空当前 Bot 的上下文。

首次升级自动将原机器人登记为“默认机器人”，沿用原数据库、加密密钥、凭证、人格、会话、统计、主动消息记录和启停状态。升级前的 SQLite 快照保存在 `/data/backups/before-multibot-*.sqlite3`。全局目录为 `/data/bots.sqlite3`；新 Bot 的独立数据位于 `/data/bots/{bot_id}/`，原默认 Bot 的数据保持在 `/data/`，不搬移也不重复导入。

归档会停止当前 Bot 并关闭其自动恢复，但保留数据；恢复后保持停止状态，需手动启动。若其 AppID 已被其他未归档 Bot 使用，需先解决冲突才能恢复。新建 Bot 默认停止、主动消息关闭，不会复制其他机器人的密钥、人格或接收者。

在“已归档”列表可以永久删除 Bot，需输入完整名称确认。删除清除该 Bot 的当前配置、密钥、聊天记录、上下文、主动消息与统计，不能在平台内恢复；不会影响其他 Bot。平台已有备份与外部备份独立保留，不随 Bot 删除自动清理。

管理 API：`GET/POST /api/bots`，`PATCH /api/bots/{id}`，`POST /api/bots/{id}/archive` 与 `restore`；永久删除使用 `DELETE /api/bots/{id}`，JSON 为 `{"name":"完整机器人名称"}`。配置、状态、模型测试与主动消息 API 分别位于 `/api/bots/{id}/settings`、`status`、`ollama/test`、`proactive`；启停使用 `/api/bots/{id}/start`、`stop`。原有单机器人 API 保留为默认 Bot 的兼容入口；所有管理 API 使用同一管理员登录保护。

## 角色记忆

每个 Bot 在“模型供应商”分别选择对话、Embedding 和可选 Rerank；在“角色记忆”启用并保存。默认关闭，不会擅自为既有 Bot 选择收费服务。策略配置需先停止 Bot，用户记忆的新增、更正与遗忘可在运行期间操作。

Embedding 支持 `openai_embedding`（OpenAI/兼容）、`gemini_embedding`（Gemini 原生）、`ollama_embedding`（Ollama 原生或 /v1 兼容）、`dashscope_embedding`（DashScope 原生）；Rerank 支持 `dashscope_rerank`、`xinference_rerank`。连接各自具有名称、URL、API Key、默认模型与用途，同类型可创建多份。Embedding 向量维度可留空使用模型默认值；Xinference 模型名称使用已部署 UID。DashScope 地址按 Key 所属地域和业务空间填写，不假定所有账号使用同一 Host。编辑连接中可执行真实模型调用测试；测试不发 QQ 消息，不计入 Bot 聊天统计。

长期记忆包含事实、偏好、边界、明确关系、共同经历和带绝对时间的约定；保留最近上下文与滚动摘要。普通对话读取当前用户的摘要、相关全文/向量召回结果，并可经 Rerank 排序，固定项和边界优先、上下文预算受限。摘要/事实整理沿用 Bot 的对话模型，默认累计 6 轮，或待处理消息闲置 30 秒后执行。嵌入与重排的实际输入用量计入 Token 总统计；服务未返回 Token 的请求不会伪造用量。嵌入/重排异常使用全文/初步检索结果，后台显示索引或任务状态。

身份边界是 Bot 所在数据库 + QQ AppID + 单聊/群聊 + 目标 + 发送者。不同 Bot 不合并 openid，同一成员的私聊与不同群各自保存。聊天档案、来源消息、摘要、事实、向量、任务和约定均使用此边界；不会把合成的主动消息提示当成用户事实。只在普通回复由 QQ 返回消息 ID 确认后加入自动整理，旧状态送达的回复不作为记忆来源。

QQ 命令：`/记住 内容` 明确保留并固定，`/查看记忆` 显示编号，`/忘记 编号` 遗忘指定条目；也可用唯一匹配的内容定位，存在歧义时不删除。后台可新增、编辑、固定、设置到期时间、查看来源和修改记录。更正或遗忘立即使旧摘要/近期上下文失效；遗忘留下排除标记与来源屏障，阻止排队任务和旧聊天回放恢复已忘信息。原始聊天档案独立保留。自然整理有来源水位与按用户顺序处理，旧重试不能覆盖新更正或把取消约定恢复为待履行。

已确认约定保存具体开始/结束时间、来源和 pending/fulfilled/canceled 状态。普通聊天与日程后台使用同一用户范围；当日新增、改期或取消同步到该用户日程，生成次日日程时覆盖已确认的对应时段。模型生成常规生活基线，再由程序投影约定，取消时仅恢复仍由该约定占用的时段，不撤销后来的独立对话修改。时间重叠的约定在日程页显示冲突，不静默取消另一条。超过约定时间不自动认定已履行，也不自动创建现实提醒或主动通知。

首次升级不批量整理全部旧聊天，避免把历史玩笑当成当前事实；管理员可对选定用户执行“整理最近聊天”，最多最近 120 条合格来源，已完成整理/遗忘屏障之前的消息不重放。更换 Embedding 模型、维度或连接配置后索引版本改变，旧向量不参与新查询；后台自动补建，也可手动重建。实际效果取决于对话模型的提取能力，可在后台核对来源并更正。

记忆 API：`GET /api/bots/{id}/users`；`GET/POST /api/bots/{id}/memory?scope_id=...`；`PUT/DELETE /api/bots/{id}/memory/{memory_id}?scope_id=...`；`GET /api/bots/{id}/memory/{memory_id}/sources?scope_id=...`；`POST /api/bots/{id}/memory/organize`、`rebuild`、`retry` 同样带 scope_id。全部需要管理员登录。数据库随 Bot 归档保留，永久删除 Bot 时一并删除。

## 每日日程

在 Bot 的“每日日程”页填写生活设定，例如“经管系大一学生，周一到周五上课，住校，周末回家”，启用并保存。日程沿用该 Bot 的人格、模型供应商和模型，生成完整的 00:00–24:00 分钟级活动、地点、分时段穿着、发型仪容和定时随机事件。生成使用独立的 6000 输出 Token 预算，不受短聊天回复长度限制；实际用量计入该 Bot 的 Token 统计。

每个 Bot 的日程独立存入自己的 SQLite；同一 Bot 的每个 QQ 用户独立保存当天安排，私聊与不同群聊的成员也分别隔离。后台选择用户后查看，URL 的 user 参数保留选择。升级前的共享日程只保留为历史，不复制给任何用户。默认北京时间，也可填写其他 IANA 时区。平台运行期间每天当地 00:00 自动更新，Bot 停止 QQ 连接时仍会更新；服务重启或漏过午夜会补生成当天日程。日程开关默认关闭，升级不会修改既有人格或启用日程。日程生成的模型请求独立允许等待 10 分钟；QQ 重置指令会立即确认收到，若生成超过被动回复时限，可稍后用查看指令读取已保存的结果。

QQ 单聊、已启用回复的群 @ 中发送 `/查看日程` 查看完整当天安排（含待发生事件），发送 `/重置日程` 重新生成当天安排。命令绕过普通回复冷却，并保留消息去重；长日程按不同 msg_seq 分段回复。指令与结果进入聊天档案，不进入模型的滚动上下文，避免提前透露随机事件。

普通回复与生成式主动消息读取当前活动、穿着和已经发生的事件；普通对话还可读取未来的活动计划以协商改约，但尚未发生的随机事件不会放入模型上下文。固定问候和真实提醒的发送时间沿用主动消息设置，不由角色虚构日程决定。重置成功后新日程立即生效；生成失败会保留原日程并显示错误，自动尝试间隔至少 5 分钟，网页或 QQ 可手动重试。修改生活设定、人格、模型或 QQ AppID 后，旧日程不再用于新配置。最近 7 天的日程保留在对应 Bot 数据库内。

启用日程后，QQ 对话中确认的当天改约会实时修改安排，无需额外指令。例如角色答应“今晚 19:30–20:30 陪你去公园散步”，对应时段会被替换。当前活动从此刻所在分钟拆分，过去与其他安排保留；因地点或活动变化而不再适用的待发生随机事件会取消。未确认的提议、假设、引用、明天的邀约、已拒绝的要求不应修改今天日程。角色能看到可协商的未来活动计划，但仍看不到尚未发生的随机事件。

回复与修改提案由同一次聊天推理产生，不为每条消息额外调用一次模型；仅在 QQ 确认该回复送达后，才将日程与修改记录一起写入数据库。发送失败、配置/日期/日程版本变化、时间冲突或试图改写过去时，不应用提案。开启联动时为回复和结构化提案至少预留 2048 输出 Token，实际 QQ 正文仍遵循最大回复长度设置。Ollama 的长日程生成使用流式接收；普通聊天仍沿用原有请求方式。

“每日日程”页每 5 秒同步：时间线上标注“对话调整”，下方“对话引起的修改”展示原安排、新安排、原因、发起用户、触发消息及对应聊天入口。可逐页查看更早修改。重置日程不会删除审计记录，旧版本改动标记为“此前版本”。修改记录按 Bot、QQ AppID、场景、目标与用户隔离。日程反复调整变长时，QQ 查看指令改用简略展示；极长日程优先展示当前附近的活动，完整内容保留在网页中。

管理 API：`GET /api/bots/{id}/schedule` 读取状态和当天日程，`POST /api/bots/{id}/schedule/generate` 生成缺失日程，`POST /api/bots/{id}/schedule/reset` 强制重置；均需要管理员登录并提供 `?scope_id={用户范围ID}`，用户范围由 `GET /api/bots/{id}/users` 获取。读取状态不会调用模型；未选用户的状态接口不会展示旧共享日程。

修改记录：`GET /api/bots/{id}/schedule/changes?day=2026-10-24&before=100&limit=20`，日期默认当天，`before` 为上一页的记录 ID，`limit` 范围 1–100。返回 `items`、`next_before` 与 `total`；状态快照同时返回最新 20 条修改。

## 聊天记录

每个 Bot 的“聊天记录”页按 QQ 单聊接收者或群聊分组，群成员共用对应群的记录视图。新收到的消息（包括冷却或忙碌期间未回复的消息）、成功发送的回复及确认送达的主动消息独立保存，失败草稿不作为已发送消息展示。记录按当前 QQ AppID 隔离。快捷查看以列表展示，气泡视图中用户在左、Bot 在右，每 5 秒刷新，可逐页加载更早记录。

升级时只导入旧数据库仍保留的模型上下文和已确认主动消息；已被旧版滚动清理的聊天无法恢复。旧上下文没有原始发送时间，显示“时间未记录”和“旧上下文”；不会把导入时间当作发送时间。清空模型上下文、修改人格或模型不会删除聊天档案。图片与表情包仅记录数量并显示占位说明，不保存原件、附件地址或 Base64。

聊天 API：`GET /api/bots/{id}/conversations?limit=50&offset=0`；消息使用 `GET /api/bots/{id}/conversations/{conversation_id}/messages?limit=100`，以 `before` 加载旧记录或 `after` 获取新记录，两个游标不能同时使用。

## 数据与配置

`app-data` Docker 卷保存机器人目录、各 Bot 的数据库与 `secret.key` 加密密钥，备份时必须备份整个卷；`ollama-data` 保存模型。上下文和聊天档案含对话正文，管理员登录后可查看聊天记录，运行日志不保存正文。

`.env` 保存管理密码，不加入版本控制。凭证保存在数据库内，需运行时编辑。修改模型、提示词或回复策略会清空旧上下文。留空 AppSecret 会保留原值。

Ollama 默认使用 `ollama/ollama:latest`，Docker 会使用已有镜像站设置。也可在 `.env` 中设置 `OLLAMA_IMAGE=你的镜像站/ollama/ollama:latest` 显式指定镜像站，避免回退直连。

`.env` 的 `OLLAMA_MODEL` 决定初始化服务拉取的模型与新数据库的默认模型；未设置时使用 `qwen3:0.6b`。Hugging Face GGUF 可直接使用 `hf.co/作者/仓库:量化类型`，例如 `hf.co/HauhauCS/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive:Q6_K_P`。已有数据库的模型选择仍以网页保存的配置为准。

当前 Docker 配置限制同时驻留一个模型、单路推理，默认上下文 8192，以控制大模型的内存占用。Ollama 仍只在容器网络内提供服务。人设在网页的系统提示词配置中编辑并保存。

不要使用 `docker compose down -v`，除非确定要删除全部配置、上下文和模型。

如需通过 HTTPS 反向代理访问，请设置 `COOKIE_SECURE=true` 与 `PUBLIC_ORIGIN`。当前配置网页支持局域网 HTTP 访问，Ollama 不对局域网开放。

## 模型供应商

“模型供应商”页上方为当前 Bot 选择供应商、模型、温度、超时和输出 Token 上限，下方统一管理共享连接；`/providers` 提供独立的连接管理入口。同一类型可添加多份连接，自定义名称或留空自动生成 `ollama-1`、`ollama-2` 等。各连接可设置默认模型，切换供应商时自动带入，之后仍可手动修改。改变默认模型不会修改已保存的 Bot 模型。

| 类型 | 基础地址示例 | 使用接口 |
| --- | --- | --- |
| Ollama 本地/外部 | `http://ollama:11434`、`https://ollama.example/v1` | 自动识别：普通地址走原生 `/api`；以 `/v1` 结尾走 OpenAI 兼容接口，也可手动指定 |
| OpenAI Compatible | `https://api.openai.com/v1` | `/chat/completions` |
| OpenAI Responses | `https://api.openai.com/v1` | `/responses`，关闭远端存储，每次发送当前 Bot 的独立上下文 |
| Anthropic Compatible | `https://api.anthropic.com/v1` | `/messages`，`x-api-key` 与 `anthropic-version` |
| DeepSeek | `https://api.deepseek.com/v1` | `/chat/completions` |

地址填写 API 基础地址，不包含最终的 `/chat/completions` 或 `/responses`。反向代理的自定义路径前缀会保留。所有类型都保留 API Key 输入；本地 Ollama 可以留空。API Key 加密保存在 `/data/providers.sqlite3`，密钥文件为 `/data/providers.key`，备份时需要一起保存。列表与编辑接口只返回“已设置”状态，不回传 Key 原文。编辑时留空保留原值，支持主动清除；更换地址或协议时，留空会清除原 Key，防止把旧凭证自动发送到新地址。

修改共享连接的协议、地址、Key 或能力设置前，必须停止使用它的 Bot，并等待正在处理的生成结束；保存会清空这些 Bot 的模型上下文，聊天档案和累计统计保留。只修改名称或默认模型不影响运行。仍被 Bot 引用的连接不能删除，归档 Bot 也计入引用；需先恢复并切换供应商，或删除该 Bot。

模型列表与生成分别测试。某些兼容服务没有 `/models`：页面会提示手动填入模型，并用“生成测试”验证，启动时不会强制拒绝这类服务。只有 Ollama 原生连接会执行本地预热，外部协议不会调用 Ollama 特有接口。生成测试使用固定测试提示词，不读取 Bot 人格或历史、不发 QQ 消息；测试用量单独显示，不累计到 Bot 聊天统计。外部模型、权限、额度和视觉能力需以对应账号的真实测试结果为准。

高级设置支持关闭 `temperature`、为 Chat Completions 选择 `max_tokens` / `max_completion_tokens`。Anthropic 默认使用兼容性较好的 `2023-06-01`，该版本温度为 0–1；选择 `2026-10-21` 时不发送温度参数。输出 Token 上限为 128–32768，默认 1024，推理模型可增大预算。回复正文与推理内容分离，不把 reasoning/thinking 字段作为回复；各协议的实际输入/输出 Token 映射到现有统计，Anthropic 缓存读取和写入的输入 Token 一并累计。

升级时自动为已有 Bot（含归档 Bot）的 Ollama 地址建立共享连接，并保留所选模型、人格、凭证、上下文、聊天档案、统计与启停状态。同地址合并为一条连接。为兼容旧数据库和 API 客户端，Bot JSON 的模型选择字段仍名为 `ollama`，新增 `provider_id` 与 `max_tokens`；实际调用协议由共享供应商决定。

供应商 API：`GET/POST /api/providers`、`PUT/DELETE /api/providers/{id}`、`POST /api/providers/test?provider_id={id}`、`POST /api/providers/test-generation?provider_id={id}`。测试时提供编辑后的连接字段，Key 留空的保留规则与保存相同；生成测试另外提供 `model`、`temperature`、`timeout`、`max_tokens`。供应商管理与所有 Bot 使用同一管理员登录保护。

协议参考：[OpenAI 文本与 Responses](https://developers.openai.com/api/docs/guides/text?api-mode=responses)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Ollama 鉴权](https://docs.ollama.com/api/authentication)。

## 常用命令

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose restart app
docker compose down
docker compose exec app pytest -q
```

配置好 QQ 凭证后，可运行 `docker compose exec app python -m app.verify` 做验收：验证登录、模型可用性、真实模型生成与 QQ 网关，再启动机器人。模型回复的发送请求会在独立测试中拦截，不会伪造 QQ 用户或发送测试消息；真实消息收发需在 QQ 中给机器人发消息验证。

图片验收可运行 `docker compose exec app python -m app.verify_images`：使用生成的测试图片、模拟 QQ 附件下载和真实 Ollama 视觉推理，检查图文消息、纯图片、GIF 抽帧、回复路由、去重及 Token 记录。最终 QQ 发送在测试内捕获，不影响生产统计。真实 QQ 客户端是否把某种表情作为图片附件下发，仍以实际消息事件为准。

主动消息验收可运行 `docker compose exec app python -m app.verify_proactive`：使用隔离数据库、真实 Ollama 生成与截获的 QQ 发送验证主动搭话和固定提醒，不给真实 QQ 用户发消息。网页“发送一条测试消息”则是真实独立主动推送，不携带用户消息的 `msg_id`；测试结果仅证明该账号和接收者在测试时可发送，不保证未来额度。

每条消息最多识别 3 张图、单张下载上限 10 MB；图片会缩小到最长边 1024 像素以控制推理开销，过大或损坏图片会返回可读提示。图片仅从 QQ 图片服务通过 HTTPS 下载，不携带机器人凭证。图片原件、附件地址与 Base64 不写入 SQLite 或运行日志；历史保留图片消息标记及机器人文字回复，后续聊天通过文字上下文延续。动图是抽帧理解，不代表逐帧分析。

## 主动消息配置

主动消息总开关默认关闭。先给机器人发一条单聊，在网页“主动消息”选择并保存接收者，再启动机器人测试推送权限。接收者和权限按 AppID 隔离，保存在独立表中，清空文字上下文不会清除接收者。QQ 拒绝主动消息后会暂停自动推送，需手动重新测试。

默认活跃时段为北京时间 07:00–00:00，每日不限次数（daily_limit=0），也可设置正整数上限。问候/搭话冷却默认 120 分钟，可设 0–1440 分钟；搭话间隔默认随机 120–240 分钟，最短和最长均可设 5–1440 分钟。启用、改变策略或收到新消息后重新安排搭话候选时间；近期仍在聊天（保护期为最短搭话间隔与 10 分钟中的较小值）、正在处理消息、连续 2 次主动问候未获回应时暂停问候和搭话（未回应阈值可设 1–20 次），收到新的单聊后恢复。一次性提醒使用固定文字，不受聊天冷却与未回应暂停影响，但仍受总开关、连接、活跃时段和日上限约束。

定时问候只在计划时刻后 2 分钟内处理，过期不集中补发；一次性提醒超过设定时间 5 分钟标记为过期。手动能力测试可在自动总开关关闭时发送，每分钟最多一次，测试计入今日发送数量。预览不发送消息，但真实模型消耗的 Token 会计入统计。

调度、接收者、发送记录和提醒均保存在 SQLite，不增加容器或 Redis。已发送任务不会重复执行；生成中重启的任务跳过，发送中重启或请求超时的任务标记“结果未知”，不会自动重发。停止机器人会暂停自动推送，模型生成过程中若收到新聊天或配置发生变化，会取消尚未发送的搭话。

当前 QQ 使用原始 `hf.co/HauhauCS/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive:Q6_K_P`，保留完整语言权重及视觉/音频投影器。本机 Docker Desktop 设置为 10240 MiB 内存、4096 MiB Swap，原始版本已完成文字生成测试。Docker Desktop 的资源上限在 Settings → Resources → Advanced 中调整；Compose 无法增加虚拟机的资源总量。

`gemma4-e4b-hauhau-q6kp:latest` 暂留作内存较少时的文字模式备选，使用同一份 Q6_K_P 语言权重，跳过视觉/音频投影器，并设置 64 批次和 mmap。

模型文件引用的是已校验的语言 GGUF SHA256；修改模型来源时应一并更新该路径。首次加载较慢，Docker 内运行使用 CPU。

### 运行日志

每个机器人都有独立的运行日志页面。支持按级别、事件分类、时间范围及关键字筛选，筛选条件保存在 URL 中。日志每 5 秒增量刷新，可暂停、加载更早记录及导出当前已加载结果。

点击事件可查看处理阶段、供应商/模型、耗时、Token 和异常类型/HTTP 状态，并沿同一次消息的处理链路查看接收、模型调用与发送结果。关联消息按需从聊天档案读取，可直接跳转完整聊天。嵌入和重排请求也记录结果与耗时。凭证自动脱敏，不保存完整模型上下文、人格、网络头或图片正文。

每个机器人保留最近 10,000 条日志。旧记录会迁移保留；升级前没有采集的耗时、Token 和处理链路无法补回。已知 QQ AppID 的历史记录在迁移时绑定原身份，修改 AppID 后不会混入新身份的日志。

### 对话 Thinking 与请求超时

在 Ollama 供应商的新增/编辑页面可设置“对话 Thinking”，默认关闭。仅普通 QQ 聊天（含看图回复）和对话生成测试读取该开关，日程生成、记忆整理、主动消息保持原有请求行为。原生 API 显式发送 `think` 布尔值，Ollama `/v1` 兼容 API 发送 `reasoning_effort`（关闭为 `none`，开启为 `medium`）。需服务版本与模型支持；其他供应商协议不追加此参数。

Thinking 开关可以在机器人运行时保存，从下一次对话请求生效，不清空上下文。供应商连接、密钥和其他协议设置仍需先停止相关机器人后修改。

每个机器人的请求超时默认 120 秒，可设置 5–600 秒（最多 10 分钟），原有保存值保留。生成测试使用相同的范围。HTTP 等待超时与 QQ 消息回复有效期分开计算，现有 QQ 过期消息检查仍然保留。

### 用户重置 `/reset`

用户向 Bot 发送 `/reset` 后，机器人先说明影响，不会立即删除。用户需在说明成功送达后的 2 分钟内发送 `/reset 确认`（也支持 `/reset confirm`）执行；发送 `/reset 取消` 或 `/reset cancel` 可取消，过期或机器人重启后需重新发起。

确认后清空当前 Bot、QQ AppID、发送者与当前单聊/群聊成员范围的短期上下文、长期记忆、摘要、向量索引和旧记忆任务，取消该用户正在生成的旧回复。后台聊天档案、人格、配置及普通日程保留，记忆产生的未来日程约定会同步移除。其他用户、群聊范围和 Bot 不受影响。确认后的清空不能通过 Bot 撤销。

命令可绕过普通聊天冷却与同用户忙碌限制；旧确认消息、提前发送但延迟处理的确认、未获得 QQ 送达回执的警告、重复事件均不能误触清空。重置后旧聊天来源被隔离，后台整理不会恢复已清空的记忆；新的聊天可以重新学习。后台“角色记忆”显示无旧记忆正文的重置记录，聊天档案将指令回复标记为“重置指令”。

### 普通聊天消息分段

“回复策略 → 消息分段”可分别为每个Bot配置：默认开启、目标段长100字、最多4个气泡、段间隔0.8秒。段长可设20–500字，气泡数1–4，间隔0–5秒。短回复保持一条，长回复优先在段落和句末断开；链接、内联代码与围栏代码块保留完整。段长是语义目标，完整长句或代码块可能更长，达到气泡上限后合并剩余内容，不丢弃尾部。原有最大回复总长度仍生效。

每段通过QQ官方回复接口依次发送，使用同一个用户msg_id与递增msg_seq。模型只调用一次，完整送达后上下文仍记为一轮；后台聊天记录按真实气泡逐条显示，发送统计按实际确认送达的气泡计数。仅调整分段配置保留既有上下文。

发送前统一剥离聊天传输对象，兼容纯 JSON、代码围栏以及“普通正文后附 JSON”的模型输出，只发送 `reply` 正文，表情包独立处理。多个冲突对象、无有效正文或无法安全解析的结构不原样发送；尾部元数据截断时可保留前面已经完整的普通正文，但不应用残缺的日程修改。混合输出中的日程修改也不执行。消息分段前再次检查正文，最近上下文读取时过滤旧版泄漏的传输数据，真实聊天档案仍保留原始发送记录。

中途发送失败、QQ未确认、回复过期、日程/记忆发生变化或用户执行已确认的/reset时，停止后续段落；不自动重发以免重复。只把已确认送达的内容归档和保存为短期上下文，未完整送达不提交整条回复的日程调整或记忆整理任务。群聊的每个气泡通过明确的父用户消息绑定来源，保持成员隔离。指令提示、日程显示与主动消息沿用现有发送方式。

### 消息防抖与会话队列

“回复策略 → 消息防抖”默认开启：每个 Bot、QQ AppID、单聊用户或群成员独立等待。最后一条消息后静默3秒再合并调用模型；默认最长收集10秒，每批最多10条。达到条数上限可提前处理。正文最多12000字符、附图合计最多3张，超出留下一批；单条本身异常沿用原有提示。

模型生成期间，新消息继续入队作为下一轮，同一会话不并发生成，不反复取消重算；不同会话最多4个普通批次并行。等待收集不占模型任务名额。原有回复冷却改为延后处理，消息不再因冷却而直接跳过。关闭防抖后仍逐条排队处理。最长收集时间不包括上一轮生成、冷却、并发容量等待；原有QQ回复有效期检查仍生效，过期消息会保留档案并记录日志。

原始消息逐条归档；模型看到按接收顺序合并的一条用户内容，上下文记作一轮，Token只统计该次模型响应。回复可继续分段发送。日志显示批次编号、合并条数和所有来源，运行概览显示等待消息数。仅调整防抖设置保留既有上下文。

缓冲存于本地SQLite，payload使用Bot现有密钥加密，终态清空临时payload，原档案保留。等待中的批次可在重启后恢复；中断于模型生成阶段可重新排队。中断于发送阶段的批次标记为发送结果不确定，不自动重发，避免重复气泡。`/reset`等指令不参与合并；确认重置后清空本用户缓冲及旧任务，防止旧内容再次恢复。

### 表情包语义库

每个 Bot 的「表情包」页可以配置独立的 Embedding / 可选 Rerank、发送概率、冷却时间、最近图片避重复数量和启用集合。图库与逐图描述共享，发送策略与每位用户的冷却独立。策略可以在机器人运行时保存，不清空上下文和长期记忆。

本次导入 `anka-afk/deepseek-fanart-meme-pack` 的 174 张素材，固定源提交 `86841e222b1c26a3d4d307e7224963e8a271f9e9`。使用 DeepSeek Flash 图片输入生成每张的画面、原文字、适用/不适用场景、情绪、语气和待核对标记；可在后台人工修订。描述原始记录保存在 `imports/deepseek-fanart-v1/descriptions/`，各记录含原图 SHA256、模型、生成时间和用量。源包权利以包内 LICENSE 为准，不包含额外商业授权。

运行数据保存在 Docker `app-data` 卷的 `/data/memes.sqlite3`、`/data/meme-assets/`、`/data/meme-sources/`。资产用 SHA256 定位，删除时停止所有 Bot 使用但保留旧聊天预览。新增自定义图片限 10 MB，支持 PNG/JPEG/WebP/GIF；上传后需补充描述、启用并构建索引。

索引复用已有四类 Embedding / 两类 Rerank 适配器，与私人记忆独立；按接口配置、模型、维度和描述修订隔离。首次配置或编辑描述后点击「构建 / 更新索引」。已完成的向量断点保留，未索引的图片不参与召回。每轮先作概率、用户冷却及最近图过滤，再进行语义检索；同一次主对话 LLM 在候选 ID 中挑选，允许不选，避免额外生成一次回复。

QQ 采用 `files` 的 `file_data` 上传取得 `file_info`，`srv_send_msg=false`，再以 `msg_type=7` 发送。上传数据不经公网静态站，不开放 Ollama 或后台。GIF/WebP 等统一转换为静态 PNG（必要时 JPEG），GIF 只发首帧；聊天预览展示对应静态结果。文字加图片总计最多四条 QQ 被动回复，图片排在文字之后；图片失败仍保留文字，未取得送达收据不计成功。reset / 日程 / 批次失效后停止后续发送；只将已确认发送的表情语义注记放进上下文。

批量描述脚本：`scripts/describe_meme_pack.py <下载包路径> <描述输出目录> <含 providers.sqlite3/providers.key 的只读凭证目录>`。使用已有 DeepSeek 供应商密钥，固定 `deepseek-flash`，三路并发、最多三次重试、逐图断点保存，保持辅助任务默认 thinking 行为。不要将供应商数据库或密钥复制到项目、前端或日志。

### 外部 NapCat 接入

新增机器人后，进入「QQ 机器人」，把接入类型选择为「外部 NapCat」。填写外部服务的登录 QQ 号、`ws://` / `wss://` WebSocket 服务地址及连接 Token。保存后点击「测试 NapCat 连接」，它仅核对登录账号和在线状态，不收消息；选择模型并启动机器人后开始处理事件。

外部 NapCat 中需启用「WebSocket 服务端」（正向 WebSocket），事件消息格式选择数组。请勿把 WebUI 管理地址或其登录 Token 填到连接字段。HayBot 不负责部署、扫码或登录外部 NapCat。Docker 中的 localhost 指容器自身；本机服务通常用 `host.docker.internal:端口`，其他机器用可达的局域网地址或配置好的 WSS 域名。

- 官方机器人与 NapCat 机器人可以同时工作。当前机器人连接方式、登录账号、Token 各自独立。
- Token 加密落库，不回传前端；空值保留旧 Token，仅在地址及账号一致时复用。更换地址/QQ 后请重新填写；可显式清除旧 Token。
- 连接前核对真实登录 QQ 号。身份不符或 QQ 未在线时拒绝启动；连接断开会重连，待确认的已发请求不自动重发。
- 支持好友私聊、群内 @ 回复（可配置是否要求 @）、QQ CDN 图片输入、原生图片表情及原始 GIF 输出。表情经 `sub_type=1` 发送，聊天档案保存原图预览。
- 复用消息防抖、分段、模型供应商、角色记忆、独立日程、reset 二次确认和主动消息策略。群聊按成员隔离；机器人自身事件忽略。
- NapCat 的账号身份使用 `napcat:<QQ号>`，与官方 AppID 隔离。切换接入或账号会清理近期上下文，并需重选主动消息接收者；旧档案、记忆及日程保留但不会跨身份检索。
- 接口回执超时或连接中断时可能无法判定远端是否已发出；不自动重试该发送，避免重复消息。事件队列最多 128 条，等待回执最多 64 个；日志会提示连接与队列错误。

### 引用回复（官方 QQ Bot / NapCat）

私聊与群聊均可理解用户引用的旧消息：模型会同时看到被引用原文、可用的作者信息，以及用户本次新发的文字。引用背景与当前表达分别标注，连续消息合并时也保留每条回复各自的引用对象；仅引用而没有新文字的消息也会接收。聊天记录中显示独立的引用预览。

官方 QQ Bot 读取 `message_type=103` 的 `msg_elements` 和 `message_scene.ext.ref_msg_idx`，支持有界的嵌套引用与卡片文字摘要。记录入站 `msg_idx`、出站消息 ID 及响应 `ext_info.ref_idx`，当事件未携带原文时，可在当前 Bot、账号与会话内按索引恢复已经归档的原文。兼容 `message_reference.message_id` 的索引查询。不调用不存在的官方单聊/群聊历史消息接口。

NapCat 读取 OneBot `reply` 消息段，优先恢复当前会话归档；未归档时通过 `get_msg` 查询并核对消息 ID、聊天类型和所属会话，查询最多等待 5 秒。原文已撤回、接口失败或无法确认所属会话时，仍处理本次新文字，明确标注原文不可读取。引用不会绕过群聊的 @ 要求。引用附件目前提供类型说明，不自动读取旧图片或文件，也不会把引用附件当成本轮已识别的图片。

协议参考：[官方单聊事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/c2c_message_create.html)、[官方群聊事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html)、[官方发送响应索引](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)。升级前的普通聊天档案会保留；旧版未记录机器人出站平台 ID，因此仅凭旧引用 ID 且没有原文的事件无法从这些旧出站记录反查。

### QQ 空间（NapCat）

在 NapCat 机器人的「QQ 空间」页面编辑说说，支持最多 2000 字、9 张配图、可见范围、草稿、一次定时发布、每日固定时间自动发布及删除本机记录的已发说说。图片单张上传上限 10 MB，规范化后发送总计最多 20 MB；GIF 作为静态首帧配图。图片独立于表情包图库，按当前 Bot 与账号隔离。

可见范围支持所有人、好友、指定好友、仅自己、指定好友不可见；指定范围需填写 QQ 号。默认仅自己可见，自动发布默认关闭。手动立即发布先保存为草稿并显示正文和可见范围确认，返回不会激活新定时任务。点击「保存定时发布」才创建一次定时任务。

「AI 生成正文」使用已保存的人设、生活设定及「可公开的生活素材」，不读取私聊、长期记忆或每用户日程。没有明确公开素材支持的事情只写感想或计划，避免声称未发生的经历。生成只填入编辑器，发布需要另行操作；开启每日自动生成后，到设定时刻直接发布。策略可在运行中保存，修改后旧的自动生成任务会失效。

定时任务需要 Bot 在线；每日任务只在时刻后的 2 分钟内发出，一次定时最晚允许 5 分钟，等待锁或模型过慢超过期限会跳过。每个账号的同一天同一时刻只建立一条每日任务，修改策略及重启不重复发布。发送结果不明、发送中断或缺少 tid 时记录为未知，不自动重试；请先去 QQ 空间核对。草稿、定时和排队任务可本地取消，已确认发布的记录可以同步删除 QQ 空间说说。

数据位于各 Bot SQLite 的 `qzone_config`、`qzone_posts`、`qzone_images` 表和同目录 `qzone-assets/`。本地记录保留 tid、状态及配图，删除说说不会删除聊天、记忆或日程。当前对接 NapCat `send_qzone_msg` 和 `delete_qzone_msg`；官方机器人不提供该页面的发布能力。

## 安卓设备（实验性）

安卓功能在 `feature/android-runtime` 分支开发。HayBot 管理 redroid Android 12 容器；每个 Bot 独占一台设备和独立数据卷。默认关闭模型操作，不改变现有聊天配置。Mac 使用 HayBot 专用 Linux VM，不使用个人 AVD；Linux 可直接运行。Windows x64 使用专用 QEMU Linux VM，不修改全局 WSL 内核。Windows/Linux 仍需对应实机验收，不能以 Mac 运行结果代替。

在**部署电脑宿主系统**安装 Python 3.10+ 后运行：

```bash
# macOS 先安装 Lima；Linux 先准备 Docker；Windows x64 先安装 QEMU、OpenSSH 并启用 WHPX。
# 可通过 HTTP_PROXY / HTTPS_PROXY 使用自己的下载代理。
python3 scripts/android_runtime.py setup
python3 scripts/android_runtime.py start
python3 scripts/android_runtime.py status
```

`setup` 会创建专用虚拟机，或在 Linux 上安装 Docker/ADB/Binder 和 UI 自动化依赖。Linux 安装脚本适用于 Ubuntu/Debian 系；不覆盖其他发行版内核。Windows 依赖 QEMU、qemu-img、ssh、ssh-keygen，需加入 PATH；安装器准备独立 qcow2 磁盘、cloud-init 和项目 SSH 密钥。Windows ARM64 暂未支持。

将 `.android-runtime/haybot.env` 中的两项配置加入项目 `.env`（不要提交凭证），再重建 app 服务：

```bash
docker compose up -d --no-deps app
```

后台进入对应 Bot 的「接入设置 → 安卓设备」，创建、启动设备后可获取画面。点击画面轻触，拖动画面滑动；先聚焦输入框再发送文字，支持中文。模型任务使用独立视觉模型、步数和时限；任务进行中可停止或人工接管。截图和 UI 资料仅在执行任务时发给所选模型供应商，请在自己的测试手机上使用。

Mac/Windows 管理器仅监听本机 `127.0.0.1:17321`；Linux 监听 Docker bridge 私有网关，使 app 容器可访问且不绑定局域网网卡。管理器使用独立 Token；ADB 只绑定专用 VM 或 Linux 宿主的回环接口。HayBot app 不挂载 Docker socket。Linux 上管理器需有当前 Docker daemon 的访问权限。远程部署应将运行管理器与 HayBot 部署在同一台宿主；外部设备连接暂未提供配置入口。

停止设备保留数据；「移除容器」也保留数据，重新启动可重建；「销毁设备数据」会二次确认并永久删除对应手机卷。任务或服务中断不会自动重放已执行的外部动作。日志保存在 `.android-runtime/manager.log`，设备清单和手机卷独立于 HayBot 的聊天数据库。`python3 scripts/android_runtime.py stop` 只停止管理器，设备和 VM 保留；Mac 可另运行 `limactl stop haybot-android` 关闭专用 VM。

### QQ 私聊手机操作与截图

在安卓设备页开启「允许 QQ 私聊操作手机」，填写授权用户 ID（NapCat 使用 QQ 号，官方渠道使用私聊用户 ID）。只有该用户的私聊能操作当前 Bot 的手机，群聊和其他用户不能获取手机画面。可使用 `/手机 任务内容`、`/手机进度`、`/停止手机`、`/手机截图`。

开启自然语言识别后，系统结合最近真实手机任务、结果和同一位主人的私聊语境判断指代。例如，先让角色去哔哩哔哩看视频，随后说「你刷的啥？给我看看」，会将真实屏幕作为普通图片发送到 QQ；若正在聊穿搭或方案，同样的「给我看看」不会直接触发手机截图。不确定时按普通聊天处理，指令入口始终可用。截图发送本身不调用视觉模型；需要操作手机的任务才把画面交给所选视觉供应商。

开始、进度、结束和失败的回应由当前对话模型结合各 Bot 的人格、最近私聊与真实操作结果生成，不再固定播报任务状态或反复附带命令。只是打开娱乐应用等不必打断的完成状态可以静默；主动询问的结果仍会自然回复。模型不可用时回退到简短事实回应，不编造版本或承诺自动重试。QQ 官方渠道受被动回复时限约束，超时可重新发 `/手机进度` 查看；通知或操作结果未知不自动重发。重置对话、变更账号/授权用户、归档 Bot 后，旧任务不能继续操作或向新范围泄露结果。

任务记录中的「查看模型返回」可查看本地保存的每步正文、结束原因与格式校验结果（最多保存8000字符，隐藏思考块和密钥格式，不保存截图或完整HTTP响应）。无效 JSON 或缺失动作参数会在执行动作前纠正一次；不会因此重复已经执行的点击。旧版任务未保存的原始返回无法还原。

### 长任务预算与继续执行

安卓任务默认按任务计划分阶段分配步数和时间。有新增的已观察链接或计划内已完成里程碑时，可以继续下一阶段；播放器时间变化不算新进展。阶段预算耗尽、同页重复操作或模型连续返回无效格式时暂停，保留已有步骤、计划、阶段总结和已收集链接。关闭自动预算后，可手动设置每阶段 1–10000 步、1–1440 分钟。

在任务记录点击「继续此任务」，会申请新的设备租约，重新观察当前页面后继续；保留原任务成果，不重放历史点击。任务授权与账号范围仍需有效。旧任务中仅由模型提到的链接显示为「历史候选」，必须重新核对，不能当作已观察到的结果。已尝试发布但结果未知的评论仍不会重复发送。

### 公开评论草稿

后台从视频标题、作者及页面证据建立内容关联并去重，无需模型复制分享链接或搜索视频 ID。评论面板隐藏标题时仅在可核对的操作链内延续关联，切换应用或换视频后重新核对。评论正文由独立公开人格生成，发布前校验正文与目标，发送后从评论列表核对；需要 @ 时还需核对目标账号与发布结果。

DeepSeek 公开评论草稿调用显式关闭推理，避免短输出预算被推理耗尽；此设置仅用于该草稿调用。空正文、截断或无效草稿会保存诊断并暂停任务，不发布。诊断中可查看结束原因、正文长度和实际用量。

分享链接收集任务点击原应用的「复制链接」后，后台使用当前设备租约读取手机剪贴板中的公开分享 URL，保存到任务进度；不经 Chrome 或浏览器地址栏。当前提取支持酷安帖子、bilibili 视频和 b23.tv 链接；其他剪贴板文字不会返回模型。旧任务里「无法读取剪贴板」的结论已过时，可从当前页面继续。

## Chrome 抖音自主浏览（浏览器分支）

进入「浏览器 → 抖音自主浏览 → 设置」，开启功能并填写角色兴趣、主人喜好和内容筛选要求。支持搜索、刷推荐、打开真实视频、播放抽样和读取评论；当前使用视觉模型理解画面与可见字幕，未接入音频理解。实时查看、放大和接管保持可用，人工接管立即撤销 Bot 操作权。登录和安全验证需要主人接管处理。

允许 Owner 私聊发起并保存 QQ 授权后，官方 QQBot 与 NapCat 均可用 `/抖音 任务内容`、`/抖音进度`、`/停止抖音`，也支持自然语言委托。QQ 权限绑定当前接入账号；群聊和其他用户不能启动任务。浏览记录保存在后台，QQ 回报以发送回执为准。

已接入按用户设置及额度执行的评论发布、真实 @、点赞、站内分享和受限私信回复，关注尚未接入。不用链接冒充 @；明确索要链接时从实际观看记录取得。验证中断时暂停并向已授权的 QQ Owner 自然求助；待核对互动提供只读核验入口，防止重复提交。详细运行方式、接口与验证边界见 [浏览器运行时说明](browser_runtime/README.md)。
