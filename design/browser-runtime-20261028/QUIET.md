# 普通模式减少窗口与声音干扰

> 2026-10-29 最新模式与平台范围见 [MODES.md](MODES.md)：固定无头，移除小红书专门支持。本文较早的 headed/实验性开关或最小化结论仅作历史记录。

2026-10-29，参考 DSH 研究后的第一步实现，仅修改浏览器运行时；未实现平台自主任务或平台适配器。

## 行为

- 所有独立 Chrome 启动传入 `--mute-audio`，包括普通模式、无头模式和环境启动探针。保留 headed 默认值及实验性 headless 设置。
- 工作台标签切换只切换实时采集和输入目标，移除 `bringToFront()`。
- 普通模式在导航、新建/切换/关闭标签、点击、按键和手势开始前捕获所属窗口状态；操作完成后恢复之前的最小化状态。操作中新增页面按所属窗口或 opener 所属窗口的记录处理。窗口检查仅访问本 Bot 的 context。
- 用户恢复成正常窗口后，下一次操作保留正常状态；不使用持续最小化轮询。高频 pointer move、滚轮和文本输入不额外逐次查询所有窗口。
- 原生窗口状态读取是异步操作，读取结束再次校验租约、页面与 generation，避免重新接管后旧输入继续执行。

## 验证

macOS arm64、Node 22.23.4、官方 Google Chrome 156.0.8078.73。隔离资料、本地合成网页；结束清理测试进程和资料。

- `npm --prefix browser_runtime test`：20 项通过，含新增窗口来源隔离、正常状态保留和窗口读取期间接管测试。
- `npm --prefix browser_runtime run test:chrome`：4 项通过，正式后台 Docker 中继端到端测试未设置 opt-in 环境，本轮跳过。
- `node --test integration/quiet.test.mjs`（在 browser_runtime 中执行）：最后一次代码修改后再次通过，收到 16 帧。覆盖最小化后导航、新建标签、来回切换、页面 target=_blank、关闭标签、实时画面、中文输入、滑块拖动；正常恢复后后续切换和新建保持正常。
- 在真实测试浏览器进程命令行确认 `--mute-audio`。没有进行系统音频回录，不声称完成声学验收。
- `git diff --check` 通过。

## 限制与生效

Chrome 先创建页面再恢复最小化，因此不能保证零闪窗或零瞬时焦点变化；不会隐藏 Dock 图标。操作结束后由站点延迟打开的窗口、原生 Chrome UI、扩展与跨系统行为未作保证。

本轮只验证 macOS；不复制 DSH 的屏幕外坐标、个人默认资料和开放调试端口。实时放大/接管接口保持现有实现。

本次未重启正式运行时、未部署。静音启动参数和新代码需要正式运行时重启，并由新代码启动 Chrome 后生效；已经启动的 Chrome 不会热更新参数。
