# 浏览器启动模式

2026-10-29，按用户最新方案：默认 `headless: false`，`headless: true` 放在实验性功能中。本文取代早期“所有会话始终隐藏”的要求。

## 行为

- 默认普通模式，可能显示窗口和 Dock/任务栏图标。独立 Bot 资料保留，不读取个人 Chrome 资料。
- “实验性功能 → 无头模式（headless）”开启时先显示风险弹窗：可能出现网站访问异常、额外登录验证、风控或账号访问受限；不能保证解决小红书 300012。取消不保存，明确确认后才保存。
- 两种模式均使用相同的实时采集和接管接口，保留放大、文字、拖动、滑动等功能。
- 按 Bot 保存；停止状态才允许修改，下次启动生效。运行中和启动/停止/保存并发时后端拒绝切换，不主动重启会话。使用同一份资料和登录隔离标记。
- 普通模式启动失败时不会悄悄回退无头模式。环境检测用临时资料完成短暂隐藏启动探针，不访问平台。
- 独立 Chrome 两种模式默认使用 `--mute-audio`；工作台标签切换不再调用 `bringToFront()`。普通模式在可能打开/切换页面的操作前记录所属原生窗口状态，操作结束恢复此前的最小化状态；正常窗口保持正常。不持续压制用户恢复窗口，异步延迟弹窗不作保证，仍可能短暂闪窗和保留 Dock 图标。
- 小红书 `error_code=300012` 或错误页文本会提示网络出口可能受限，建议停止自动重试、用普通 Chrome 检查同一网络。无头模式额外提示可停止后关闭该选项。错误原因不作确定判断，不自动修改 UA、启用 stealth 或伪造指纹，也不自动刷新。
- `observe` 遇到该错误返回 `site_access_blocked`，供后续任务循环接入。目前没有浏览器自主任务或 QQ 错误通知。

## 本轮验证

macOS arm64、Node 22.23.4、Google Chrome 156.0.8078.73。全部使用隔离资料与合成页面；小红书错误页通过 Playwright 路由本地响应模拟，没有用真实账号验证风控解除。

| 检查 | 结果 |
| --- | --- |
| 浏览器单元/API | 18 项通过：默认值、明确确认、持久化、Bot 隔离、参数限制、启动竞争、300012 域名限制以及原有输入/鉴权/登录隔离 |
| 后台浏览器/多 Bot/应用回归 | 26 项通过：新增设置的鉴权、来源、布尔类型、风险确认与固定 Bot 映射 |
| 前端原有回归及构建 | 18 项通过，构建成功；已有 jmuxer 与包体积提示保留 |
| 真实 Chrome 集成 | 3 项通过：两种模式的 JPEG 实时画面、拖动、中文输入、资料保留、登录隔离、模拟 300012；另含既有隐藏进程与完整手势测试 |
| 正式工作台端到端 | 1 项通过：默认普通模式→接管与拖动→取消风险弹窗不保存→确认开启→刷新保留设置→无头模式接管与拖动→同资料保留→另一 Bot 默认普通模式；继续覆盖登录隔离、放大、主题、窄屏与退出撤销 |

端到端使用临时容器 `haybot-headless-mode-validation`（18081）和临时宿主（17323），未改动线上 8080。测试结束清理容器、临时凭证、浏览器进程和资料。
