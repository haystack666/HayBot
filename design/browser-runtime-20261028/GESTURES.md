# 滑动与拖动修复验收

日期：2026-10-29。环境：Node 22.23.4、macOS arm64、官方 Chrome 156.0.8078.73。

原型此前仅把 canvas 的 click 转发成一次 mouse.click，没有按下、移动、松开的连续事件，无法操作滑块和拖动控件。滚轮此前不携带位置，内部独立滚动区域可能收不到事件；触摸滑动没有实现。

现已加入 pointer 手势链路，前端捕获指针、后端保持按住状态，直到结束或取消。自动模式下鼠标拖动网页控件、触摸滚动页面；可以手选拖动/滑动。滑动映射为桌面网页滚轮，不宣称远端支持原生多点触摸。

滚轮携带实际 viewport 坐标，处理像素、行和页三种单位。前端保留一个待发送位置和一份待发送滚轮累计量；操作绑定会话、租约、标签、generation 和画面连接版本。取消时释放在页面外，避免丢失连接变成一次意外点击；服务端在导航、接管变更、断线及超时后也会释放手势。

## 验收证据

新增真实 Chrome 端到端测试启动独立的原型服务、目标 Chrome 与查看端 Chrome，所有资料在测试临时目录，关闭后清理。没有使用正式 Bot、个人 Chrome 资料或真实社交平台。

- 普通画面拖动 range 滑块，从约20拖到至少70；自定义拖动控件移动超过100 CSS像素。
- 鼠标放在嵌套滚动区，横向与纵向滚动均生效，外层页面仍保持 scrollY=0。
- 滑动模式下鼠标上推、自动模式下真实触摸事件上推，都使嵌套区域滚动。
- 放大后反向拖动滑块到40以下；黑边点击不创建手势。
- 按住滑块时关闭查看端，后端撤销租约并释放按键。
- 单元测试覆盖黑边/边框/放大坐标、滚轮单位、拖动生命周期、接管抢占释放、滑动取消不点击和无效参数。

最终回归：`npm --prefix browser_runtime test` **11/11 通过**；`npm --prefix browser_runtime run test:chrome` **2/2 通过**，完整运行约17秒。Chrome 测试按文件串行执行，降低同机多个真实浏览器并发带来的资源影响。手势用例等待实际手势回执结束后才开始下一个操作，不把本地鼠标松开当作远端已处理完成。

手工通过原型实时画面操作：滑块20→82，拖动控件移动约288 CSS像素，嵌套区滚动后再切换滑动模式反向推动，界面显示滚动位置变化。截图：`prototype/browser-gestures.png`。

新增用例是本地合成网页的功能验证，真实平台自定义播放器、HTML 拖放与跨域复杂控件仍需分别验收。工作台、Bot/QQ 正式接入范围没有变化。
