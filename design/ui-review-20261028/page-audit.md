# 全站页面审查与入口映射

审查日期：2026-10-28。此文档依据当前前端实现，不修改生产页面或业务规则。手机页另见 `android-audit.md`。

## 判断

目前不是没有统一组件。`components/console.jsx` 已统一 `Panel`、`Field`、`Notice`，`index.css:37–47` 已有页面留白、标题、表单、卡片尺度。主要问题是：所有信息都按“标题＋解释＋完整表单＋记录”逐张堆叠，卡片内部的轻重缓急没有区别。用户进入页面首先看到配置说明，实际要看的聊天、日记、图片、执行结果反而在下面。

不能简单把所有东西折叠。现有导航已经因为折叠而难找：`BotNavigation.jsx:5–10` 将手机放在“接入设置”，群聊设置则没有导航项；所有组默认关闭（`readGroups`），用户必须猜某功能在哪个分组。建议主要目的地常驻显示，低频参数才放在明确命名的标签页或抽屉。

## 具体证据与重构重点

1. `ConnectionPage.jsx:28` 直接嵌入 `GroupChatSettings`，连接页由连接参数延伸到角色名字、Owner 关系、公开人格、群兴趣、群级覆盖和决策记录。`GroupChatSettings.jsx:47` 还提示“页面底部的保存按钮”，实际全局保存位于 `App.jsx` 页头；这类方向提示会误导寻找操作。
2. `MemoryPage.jsx:25–34` 策略占第一整块，然后才出现用户选择；`UserScopeSelector.jsx:34` 把一个用户下拉包成完整 Panel。`MemoryPage.jsx:93` 再附最近 50 条修改记录。内容页承担设置、检索状态、数据浏览、审计四种目的。
3. `DiaryPage.jsx:43–59` 先放完整说明＋习惯表单，`61–78` 才有日记列表与阅读。应让阅读成为默认视图。设置单独保存且支持运行时修改，不能误套其他页“先停止”全局提示。
4. `SchedulePage.jsx:61–74` 先写生活模板，`77` 才出现今日日程；用户范围又在外层占卡片。时间线应是第一视野，模板属于低频配置。
5. `MemesPage.jsx:74–88` 先是策略和索引，图库直到 `89` 才出现，而且说明明确“图库由所有机器人共享”。`ProvidersPage.jsx:83–98` 同一页先配当前 Bot 再管理共享供应商。两页均需要显式作用域设计。
6. `ConfigurationPages.jsx:13` 将人格、防抖、分段、上下文管理都放在一条长页面；其中清全部上下文与普通编辑层级近似。应按“身份表达 / 对话行为 / 数据维护”分开。
7. `ProactivePage.jsx:36–80` 同时放基本设置、搭话、问候、预览、提醒、推送状态、发送记录。应让规则和投递状态成为默认，独立编辑、预览和记录流程。
8. `QzonePage.jsx:77–105` 同时承载编辑器、长策略表单、完整动态记录。应拆成动态/草稿、写作、自动分享三个任务区域。
9. `BotsPage.jsx:56` 进入工作台仍叫“进入配置”，后续侧栏又全部称“机器人配置”；而其中多半是浏览/运行任务。这会给入口分类带来错误心智。
10. `App.jsx` 将停止/启动机器人放在几乎每个页面页头，又按 page 判断是否显示全局保存；日记、表情、空间、手机各有局部保存。统一设计不能假装业务保存语义相同：建议统一视觉位置、未保存提示与生效说明，同时保留实际独立保存范围。

## 统一排版约束

- 页面只有一个标题；标题下面是紧凑范围与状态行，再是标签页/筛选和主体内容。
- 同一页面只突出一个主要动作，例如“新建任务”“写这一天”“添加记忆”。机器人运行控制固定在 Bot 状态区域，不与每页主操作竞争。
- 内容型页默认展示内容；设置型页默认展示概要和编辑入口；日志/历史默认列表，点开详情。
- 不用大段灰色正文解释每个技术参数。短说明紧贴字段，操作后果、作用范围和当前异常保留；教程、协议细节放帮助或高级设置。
- 常用主导航不折叠。每个标签页有名称、数量或状态摘要，不能用只有图标的隐蔽入口承载唯一功能。
- 所有共享操作显示“共享资源”标签和影响范围；所有用户数据都显示用户与私聊/群聊范围。切换 Bot 应明确改变标题、范围条和数据。
- 统一列表行高、输入框/按钮高度、标题字号、间距、圆角和状态颜色；密度来自去掉重复容器与长说明，不靠把正文压到 10px。
- 窄屏先变为“列表 → 详情”导航，不把双栏各自变成长屏继续堆叠；详情抽屉可全屏显示，底部保存始终可达。

## 原型应能验证的路径

1. 从任意页找到群聊公开人格，识别它只对普通群友生效；看见角色身份、Owner 关系和手机授权不是一个字段。
2. 打开日记立即阅读一篇，再打开写作设置与历史版本，返回时保留选择。
3. 切换用户范围查看记忆/日程，切换 Bot 后不把另一 Bot 的名字或示例内容沿用。
4. 从 Bot 模型分配跳到共享供应商，再返回当前 Bot；从 Bot 表情策略跳到共享图库，范围标识准确。
5. 从群聊记录找到未回复原因，再跳到对应日志；无需到“QQ 连接”猜入口。
6. 从空间草稿预览进入发布确认；清楚区分“生成预览”“保存草稿”“真实发送/发布”。原型一律仅做本地演示。
7. 日记、记忆、表情图库和手机页首屏均有实际内容，不出现完整初始化/配置记录抢占首屏。
