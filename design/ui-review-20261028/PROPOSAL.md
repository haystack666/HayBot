# HayBot UI 与排版整理提案

审查日期：2026-10-28。范围：当前全部 13 个 Bot 功能页、机器人管理、共享供应商入口，以及登录/创建流程。核对了页面源码、导航、公共组件及运行中页面。方案仅新增于 design/ui-review-20261028，不改动正式前端或后端。

## 设计判断

现有基础组件并不缺统一；主要问题是信息层级与入口归属。页面把内容、设置、操作、历史、故障诊断全铺成大卡片，常用入口被低频内容压到下方。折叠导航进一步降低了可发现性。

因此本轮不以缩小所有字号、隐藏所有说明来换取密度，而是：
- 常用入口常驻，页面默认展示主要内容和当前工作。
- 常规设置进入有名称的标签页，单项详情进入侧抽屉。
- 历史记录使用紧凑列表，长正文、步骤和诊断按需展开。
- 长说明改为短提示与连接帮助；异常时提供清楚的处理入口。
- 黑白灰构成界面主体。颜色只表达状态和风险，不为模块任意着色。
- 浅色、深色和跟随系统都使用同一套组件、间距与层级。

## 新的信息架构

| 常驻导航 | 页内入口 | 解决的问题 |
|---|---|---|
| 工作概览 | 当前状态、待处理、常用入口、最近任务 | 首屏回答“有没有问题、该做什么” |
| 会话记录 | 全部会话、群聊会话；跳转群聊参与设置与回复链路 | 保留现有只读会话能力，让行为设置可发现 |
| 手机工作台 | 工作台、任务记录、应用与设备、任务设置 | 手机不再藏在接入设置里；高频操作与低频初始化分开 |
| 角色与群聊 | 身份与私聊、Owner 关系、群聊参与、公开表达、回复设置 | 拆出埋在 QQ 接入中的群聊行为；区分人格作用范围 |
| 角色记忆 | 记忆内容、修改记录、记忆设置 | 内容优先，用户范围变紧凑工具栏 |
| 每日日程 | 今日日程、历史与变更、日程设置 | 先看今天，不先填写生活设定 |
| 私人日记 | 日记本、写作习惯 | 正文在首屏，写作设置不挡阅读 |
| 主动互动 | 搭话与问候、一次性提醒、QQ 空间、发送记录 | 合并同属主动表达的入口，具体流程保留分区 |
| 表情素材 | 共享图库、当前 Bot 策略；索引状态抽屉 | 先看素材；区分共享资源和个体配置 |
| 连接与模型 | QQ 连接、模型分配 | 连接页只负责接入与分工，行为配置移出 |
| 运行日志 | 筛选列表、事件详情、相关会话/任务链路 | 摘要快速扫描，长诊断按需查看 |
| 机器人管理（侧栏底部） | 全部机器人、创建、归档 | “进入配置”改为“打开工作台” |
| 共享供应商（侧栏底部） | 目录、连接编辑、被使用情况 | 与当前 Bot 的模型分配明确分开 |

导航组不再折叠。窄屏整体收进导航抽屉。提供“查找功能”，可以用“回复策略”“初始化记录”“公开评论人格”等旧名称找到新位置。功能搜索是导航增强提案；不意味着现有后台已有全局数据搜索。

### 原页面迁移对应

| 原入口 | 新归属 |
|---|---|
| 运行概览 | 工作概览 |
| QQ 机器人：凭证、WS、接收场景、连接步骤 | 连接与模型 → QQ 连接；连接步骤进入帮助抽屉 |
| QQ 机器人：群聊人格、参与方式、群覆盖、判断记录 | 角色与群聊 → 群聊参与；记录链接到日志 |
| 回复策略：基础人格 | 角色与群聊 → 身份与私聊 |
| 回复策略：防抖、分段、长度、上下文 | 角色与群聊 → 回复设置；清理保留独立范围确认 |
| 模型供应商：当前 Bot 对话/记忆模型 | 连接与模型 → 模型分配 |
| 模型供应商：共享连接 | 共享供应商 |
| 安卓：视觉模型 | 连接与模型 → 模型分配，手机任务设置保留直达链接 |
| 安卓：兴趣、筛选、执行预算/采样/平台权限 | 手机工作台 → 任务设置 |
| 安卓：公开评论风格 | 角色与群聊 → 公开表达；手机设置保留直达链接 |
| 安卓：设备、接管、初始化、任务/发布记录 | 手机工作台各标签和详情抽屉 |
| 角色记忆、每日日程、私人日记 | 保留各自常驻入口，统一内容 / 设置 / 历史层级 |
| 表情包 | 表情素材 → 共享图库 / 当前 Bot 策略 |
| 主动消息 + QQ 空间 | 主动互动内独立标签 |
| 聊天记录、运行日志、机器人管理 | 保留独立入口，统一列表和详情交互 |

## 手机页面：本轮重点

默认桌面布局为实时画面与任务区域并排，主操作无需滚过配置表单。初始化收敛为“初始化完成 · 6 项就绪 / 查看详情”一行。详细安装版本、来源和历史放在“应用与设备”或初始化抽屉。

任务历史默认展示目标、时间/耗时、执行状态、结果回传状态。点击对应任务才展开成果、步骤、核验依据和模型诊断。

“手机任务完成”和“QQ 已送达”是两个状态。例如手机完成但回传失败时，显示“已完成 / QQ 待重试”，处理按钮只重试结果回传，不重新执行手机任务。

人工接管与 Owner 登录保留不同语义。人工接管暂停自动任务；登录模式暂停模型取图。应用登录完成后才恢复任务。危险设备操作收在设备管理的高级区，并使用红色强调。

## 统一视觉与交互规则

- 颜色：黑白灰为主；主按钮浅色黑底、深色白底；删除/销毁为红色；警告和待处理为琥珀色；成功仅在状态标记中使用克制的绿色。
- 字号：页面标题 22–25px，区块标题 14–15px，正文与表单 12–13px；日记正文保留较宽松行高。正式实现应结合用户实际屏幕验证，不能仅靠小字号增加密度。
- 间距：页面边距 24–32px，区块间距 16–20px，表单使用统一网格。长记录采用行布局而非卡片套卡片。
- 按钮：每个区域一个主要动作；其他动作用次按钮或文字链接。停止 Bot 收到运行管理，不在阅读页、图库等页面重复出现。
- 保存：视觉统一为底部保存条；保持各功能实际保存边界。不能为所有配置强制“停止 Bot 后保存”。修改作用于当前 Bot 或共享资源时明确标注。
- 表单：默认显示常用项；高级设置折叠。错误靠近字段展示；帮助不长期占用大块卡片。
- 状态：文字与图标配合，不只靠颜色。空状态、未配置、失败、等待接管要有各自行动入口。
- 深色：页面、卡片、输入、下拉、表格、抽屉、弹窗、提示、禁用态都采用对应 token；危险操作保持红色语义。
- 响应式：宽屏采用主从布局，窄屏改纵向；任务内容优先，导航成为抽屉，表格在自身容器内滚动。

## 不能因整理 UI 而改变的行为

- Bot 身份与数据隔离不能改变；林诗语和大肥鱼分别配置。
- Owner 私聊身份、群成员身份、手机授权身份和各平台账号按用途分别绑定；官方 OpenID 不能自动与 QQ 号或群 OpenID 合并。
- 群聊人格不覆盖 Owner 私聊人格；公开评论人格不带入私人上下文。
- 角色兴趣由用户填写，不能从人格自动推导；兴趣配置只保留一处编辑来源，其他位置使用摘要和直达链接。
- QQ 官方和 NapCat 的能力差异明确展示，例如官方 QQ 不支持当前空间发布能力。
- 日记保存不主动发送完成通知；现有只读会话界面不伪装成消息发送器。
- 素材、供应商的共享范围与每个 Bot 的策略范围不可混淆。
- 已存在功能的入口迁移必须保留旧路由兼容或跳转，避免书签失效。

## 原型使用与范围

打开 index.html 或本机预览地址即可。preview.html 为汇总后的单文件版本，可以离线打开，不依赖外部字体、CDN 或后端。

已演示：全部导航、页内标签、手机初始化与任务详情、功能搜索、日记切换、Bot 切换、设置修改与内存保存、平台配置、主题切换、窄屏导航。

所有聊天、日记、状态与任务均为合成示例。创建/发布/安装/销毁等动作只演示入口和反馈；不操作真实服务。详情并非完整业务实现。本轮不部署正式页面。

## 建议实施顺序

1. 先统一壳层、导航、主题 token、按钮、表单、列表、抽屉和保存条；保留旧路由跳转。
2. 改手机工作台、任务列表与详情，将初始化和设置迁出默认页。
3. 将群聊行为从 QQ 接入拆出，整理角色/Owner/公开表达的归属与直达链接。
4. 改日记、记忆、日程和图库为内容优先；主动互动按工作流整合。
5. 逐页检查原功能入口覆盖、保存行为、Bot/用户作用域、两种 QQ 接入、浅深色和窄屏布局。

全量源码证据与更细的能力映射见 page-audit.md 和 android-audit.md。
